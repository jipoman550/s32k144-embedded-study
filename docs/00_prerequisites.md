# 2 필수 컴퓨터 기초

임베디드의 핵심은 **하드웨어가 어떻게 동작하는지** + **C 코드가 하드웨어를 어떻게 제어하는지** 이 두 가지다.

따라서 다음 개념들이 필요함:

## ✓ 비트와 바이트

### 8-bit / 16-bit / 32-bit 차이

임베디드 프로그래밍(특히 C언어)에서는 `int`나 `long` 같이 컴파일러에 따라 크기가 달라질 수 있는 애매한 표현 대신, **`<stdint.h>`에 정의된 크기가 명시된 자료형**을 사용하는 것이 원칙이다. 이는 하드웨어 레지스터의 크기와 변수의 크기를 정확히 일치시켜야 하기 때문이다.

**데이터 크기와 표현 범위**

S32K144는 **32-bit MCU**이다. 이는 CPU가 한 번에 처리하는 데이터의 크기와 레지스터의 크기가 **32비트(4바이트)**라는 뜻이다.

* **8-bit (`uint8_t`)**
    * **크기:** 1 Byte
    * **범위:** 0 ~ 255 ($2^8 - 1$)
    * **용도:** 문자 데이터(`char`), 통신 버퍼(UART/SPI)의 한 바이트, 작은 상태 플래그 값.
* **16-bit (`uint16_t`)**
    * **크기:** 2 Byte
    * **범위:** 0 ~ 65,535 ($2^{16} - 1$)
    * **용도:** PWM 주기 값, ADC 변환 값(보통 10~12비트 해상도이므로 16비트에 담음).
* **32-bit (`uint32_t`)**
    * **크기:** 4 Byte
    * **범위:** 0 ~ 4,294,967,295 ($2^{32} - 1$)
    * **용도:** **S32K144의 레지스터 값**, 메모리 주소(포인터), 타이머의 전체 카운트 값.

> **💡 핵심**
> S32K144의 레지스터는 대부분 **32비트**이다. 따라서 레지스터 값을 읽거나 쓸 때는 주로 `uint32_t` 변수를 사용해야 데이터 손실 없이 정확하게 제어할 수 있다.

### 비트마스킹(AND, OR, SHIFT)

MCU 제어의 핵심은 **"32개의 전구(비트) 중 내가 원하는 전구 하나만 끄거나 켜는 것"**이다. 이를 위해 사용하는 기법이 바로 비트마스킹이다.

**1. SHIFT 연산 (`<<`, `>>`) : 위치 이동**

비트를 원하는 위치로 이동시킨다. 주로 **"몇 번째 비트를 건드릴 것인가"**를 지정할 때 사용한다.
* `1 << n`: 1이라는 값을 왼쪽으로 n칸 이동시킨다. (n번째 비트만 1이 됨)

```c
(1 << 0)   // 0000 0001 (0번 비트)
(1 << 3)   // 0000 1000 (3번 비트)
(1 << 12)  // 12번 비트만 1, 나머지는 0
````

**2. OR 연산 (`|`) : 특정 비트 켜기 (Set)**

이미 켜져 있는 비트는 건드리지 않고, **내가 원하는 비트만 강제로 1로 만들 때** 사용한다.

  * **논리:** 0과 1이 만나면 1이 되고, 1과 1이 만나도 1이 된다. (덧칠하기 개념)
  * **공식:** `레지스터 |= (1 << 핀번호);`

<!-- end list -->

```c
// 예시: GPIOA의 12번 핀을 1로 만들기 (Set)
// 기존값: 0000 ... 0000 (가정)
// 마스크: 0000 ... 1000 (1 << 12)
// 결과 : 0000 ... 1000 (12번 비트가 켜짐)

GPIOA->PDDR |= (1 << 12);
// 해석: GPIOA의 PDDR 레지스터의 기존 값은 유지하되, 12번째 비트만 '1'로 설정하라.
```

**3. AND 연산 (`&`) : 특정 비트 확인 또는 끄기**
두 가지 용도로 사용된다.

**(1) 확인 (Check / Read)**

특정 비트가 1인지 0인지 검사할 때 사용한다.

  * **논리:** 둘 다 1일 때만 1이 된다.

<!-- end list -->

```c
// 예시: 버튼이 연결된 3번 비트가 1인지 확인
if (GPIOA->PDIR & (1 << 3)) {
    // 3번 비트가 1이라면(눌렸다면) 이 안의 코드를 실행
}
```

**(2) 끄기 (Clear) - 중요\!**

특정 비트를 0으로 만들려면 \*\*"그 위치만 0이고 나머지는 1인 마스크"\*\*와 AND 연산을 해야 한다. 이때 `~`(NOT) 연산자를 사용한다.

  * `~ (1 << 3)` : `0000 1000`을 뒤집어서 `1111 0111`로 만든다.
  * **공식:** `레지스터 &= ~(1 << 핀번호);`

<!-- end list -->

```c
// 예시: 12번째 비트 끄기
GPIOA->PDDR &= ~(1 << 12);
// 해석: 12번째 비트만 0으로 만들고(끄고), 나머지 비트는 원래 값 그대로 둬라.
```

> **📝 비트마스킹 3대 공식 요약**
>
> 1.  **켜기 (Set):** `REG |= (1 << n);`
> 2.  **끄기 (Clear):** `REG &= ~(1 << n);`
> 3.  **확인 (Check):** `if (REG & (1 << n))`

## ✓ 메모리 개념

임베디드 시스템에서는 PC와 달리 메모리 자원이 매우 제한적이다. 따라서 내가 작성한 코드와 변수가 **"물리적으로 어느 공간에 저장되는지"** 명확히 이해해야 한다.

### 1. ROM(Flash) vs RAM(SRAM)
가장 큰 차이는 **"전원을 껐을 때 데이터가 날아가느냐"**이다.

| 구분 | Flash Memory (ROM 역할) | SRAM (RAM 역할) |
| :--- | :--- | :--- |
| **특징** | 비휘발성 (전원을 꺼도 데이터 유지) | 휘발성 (전원을 끄면 데이터 삭제) |
| **용도** | **코드(Code), 상수(const)** 저장 | **변수(Variable), 스택(Stack)** 저장 |
| **속도** | 읽기는 빠르지만, 쓰기가 느림 | 읽기/쓰기 모두 매우 빠름 |
| **비유** | 인쇄된 교과서 (내용이 안 바뀜) | 공책 (썼다 지웠다 가능) |

* **실행 과정:** 전원이 들어오면 CPU는 **Flash**에 저장된 명령어들을 읽어서 실행하고, 계산에 필요한 값들은 **SRAM**에 저장하며 동작한다.
* **펌웨어 굽기:** 우리가 "보드에 코드를 다운로드한다(Flashing)"는 행위는 PC에서 만든 바이너리 파일(.elf/.hex)을 MCU의 **Flash Memory** 영역에 굽는 것을 의미한다.

### 2. 스택(Stack) vs 힙(Heap)
SRAM(RAM) 영역은 크게 스택과 힙으로 나뉘어 사용된다.

**(1) 스택 (Stack)**
* **자동 관리:** 함수가 호출될 때 생성되고, 함수가 끝나면 자동으로 사라지는 영역.
* **저장 대상:** 지역 변수(Local Variable), 매개변수, 리턴 주소.
* **특징:**
    * 속도가 매우 빠르다.
    * LIFO(Last In First Out) 구조다.
    * **주의:** 임베디드에서는 스택 사이즈가 작기 때문에(보통 몇 KB), 너무 큰 배열을 지역 변수로 선언하거나 재귀 함수를 깊게 쓰면 **Stack Overflow**가 발생하여 시스템이 뻗을 수 있다.

**(2) 힙 (Heap)**
* **수동 관리:** 프로그래머가 필요할 때 할당하고(`malloc`), 다 쓰면 직접 해제(`free`)해야 하는 영역.
* **저장 대상:** 런타임에 크기가 결정되는 동적 데이터.
* **⚠️ 임베디드 주의사항:**
    * 자동차(AutoSAR)나 고신뢰성 임베디드 시스템에서는 **힙(malloc) 사용을 극도로 자제하거나 금지**한다.
    * 이유: 메모리 누수(Leak) 위험과 메모리 파편화(Fragmentation)로 인해 시스템이 예기치 않게 멈출 수 있기 때문이다. (가능하면 전역 변수나 스택을 사용한다.)

### 3. 포인터가 중요한 이유
C언어 초보자에게 포인터는 어렵지만, 임베디드에서는 **생존 필수 도구**이다. 그 이유는 두 가지다.

**(1) 하드웨어 제어 (Memory Mapped I/O)**

임베디드에서 모든 주변장치(LED, UART, Timer 등)는 **특정 메모리 주소**를 가지고 있다.
* 예: "0x400FF000 번지에 1을 쓰면 LED가 켜진다."
* C언어에서 특정 주소에 값을 쓰려면 포인터가 필수다.

```c
// 0x400FF000 주소를 포인터로 캐스팅하여 값을 대입
*(volatile uint32_t *)0x400FF000 = 1;
```
우리가 사용하는 GPIOA->PDDR 같은 매크로들도 내부를 까보면 결국 위와 같은 포인터 연산이다.

**(2) 효율성 (Pass by Reference)**

제한된 RAM을 아끼기 위해, 데이터를 복사하지 않고 주소만 넘겨서 처리해야 한다.

구조체(Struct) 덩어리가 클 때, 이를 함수 인자로 그냥 넘기면 복사가 일어나 메모리와 시간이 낭비된다.

포인터로 주소만 넘기면 4바이트(32-bit CPU 기준)만 사용하면 되므로 훨씬 효율적이다.

## ✓ C 기초

너는 이미 프로그래머니까 가능하겠지만

임베디드에서는 특히 아래가 중요함:

### 1. 구조체 (struct)와 메모리 매핑
임베디드 SDK에서 `FTM0->CONTROLS[0].CnV`와 같은 코드를 보게 된다. 이는 하드웨어 레지스터들이 메모리에 순서대로 배치되어 있기 때문에, 이를 **구조체로 묶어서 관리**하기 위함이다.

*   **원리:** 구조체의 멤버 변수들은 메모리에 연속적으로 할당된다(Padding 주의).
*   **활용:** `FTM_Type`이라는 구조체를 만들고, 그 시작 주소를 `0x40038000`으로 포인터 연결하면, 구조체 멤버에 접근하는 것이 곧 하드웨어 레지스터에 접근하는 것이 된다.

### 2. 비트필드 (Bitfield)
구조체 내부에서 비트 단위로 변수를 쪼개는 문법이다.
```c
struct {
    uint32_t EN : 1;   // 1비트
    uint32_t MODE : 3; // 3비트
} CTRL;
```
*   **장점:** 비트마스크 연산 없이 `CTRL.EN = 1;` 처럼 직관적으로 코딩 가능.
*   **단점:** 컴파일러마다 비트 배치 순서(MSB 먼저 vs LSB 먼저)가 달라서 **이식성이 매우 나쁨**. 따라서 표준 임베디드 코드(MISRA-C)에서는 비트필드 대신 **비트마스크 연산(`|`, `&`)** 사용을 권장한다.

### 3. 포인터 (Pointer)와 하드웨어 주소
앞서 설명했듯, 임베디드에서 포인터는 **"하드웨어의 물리적 주소"**를 가리키는 리모컨이다.
```c
#define PORTD_BASE  (0x4004C000u)
#define PORTD       ((PORT_Type *)PORTD_BASE)
```
위 매크로는 `0x4004C000`이라는 숫자를 `PORT_Type` 구조체의 주소로 형변환한다. 이제 `PORTD->PCR[0]`으로 접근하면 해당 메모리 번지를 제어할 수 있다.

### 4. volatile (최적화 방지) - ⭐ 필수 개념
컴파일러는 똑똑해서 불필요해 보이는 코드를 삭제(최적화)한다. 하지만 임베디드에서는 이게 독이 된다.

*   **상황:** 버튼 상태를 기다리는 코드
    ```c
    // volatile이 없다면?
    while (*button_addr == 0);
    ```
    컴파일러 생각: *"어? `button_addr` 값은 코드 안에서 아무도 안 바꾸네? 그럼 계속 0이겠지?"*
    최적화 결과: `while(1);` (무한루프) 또는 아예 코드 삭제.

*   **해결:** `volatile` 키워드를 붙이면 **"이 변수는 언제든 외부 요인(하드웨어, 인터럽트)에 의해 바뀔 수 있으니 최적화하지 말고 매번 메모리에서 다시 읽어라"**라고 지시하는 것이다.
    *   **모든 하드웨어 레지스터 정의에는 `volatile`이 붙어 있다.**

### 5. static (범위와 수명)
임베디드 C에서는 `static`의 두 가지 용법을 명확히 구분해야 한다.

1.  **함수 내부 (`static local variable`):** 함수가 종료되어도 값이 사라지지 않고 유지된다. (용도: 함수 호출 횟수 카운팅, State Machine의 이전 상태 기억)
2.  **전역 변수/함수 앞 (`static global`):** **해당 `.c` 파일 내부에서만** 접근 가능하다. (용도: **정보 은닉**. 다른 파일에서의 접근을 막아 모듈화를 강화함)

### 6. 함수 포인터 (Function Pointer)
함수의 주소를 담는 포인터 변수다.
*   **인터럽트 벡터 테이블:** MCU가 시작될 때 각 인터럽트가 발생하면 실행할 함수들의 주소를 배열(테이블)로 가지고 있다. 이때 함수 포인터가 사용된다.
*   **콜백(Callback) 함수:** 특정 이벤트가 발생했을 때 호출될 함수를 등록할 때 사용한다. (예: `LPUART_DRV_InstallRxCallback(...)`)

# 3 MCU 기본 개념

본격적인 주변장치를 배우기 전에 알아야 하는 최소한의 MCU 개념들이다. PC 프로그래밍과 가장 다른 점이 바로 이 부분이다.

## ✓ MCU (Microcontroller Unit)란?

**"작은 컴퓨터 한 대를 칩 하나에 집약시킨 것"**이다.
PC는 CPU, RAM, HDD(SSD), 그래픽카드가 모두 따로 꽂혀 있지만, MCU는 이 모든 것이 손톱만한 칩 하나에 들어있다(SoC: System on Chip).

*   **Core (CPU):** 사람의 뇌. 연산을 담당한다. (S32K144는 **ARM Cortex-M4F** 코어를 사용)
*   **Memory:** 책상(SRAM)과 책장(Flash).
*   **Peripherals (주변장치):** 사람의 팔, 다리, 눈, 귀. CPU가 외부 세상과 소통하는 도구들이다.

## ✓ 주변장치 (Peripheral)

CPU 코어 자체는 덧셈, 뺄셈밖에 못 한다. 실제로 LED를 켜거나 모터를 돌리는 건 **주변장치**가 한다.

*   **GPIO:** 전기를 껐다 켰다 함 (LED, 스위치).
*   **Timer/PWM:** 시간을 재거나, 펄스를 만들어 모터 속도를 조절함.
*   **ADC:** 아날로그 전압(온도, 빛, 가변저항)을 숫자로 읽어들임.
*   **Communication (UART, CAN, SPI):** 다른 칩이나 PC와 데이터를 주고받음.

> **핵심:** 임베디드 개발자는 이 주변장치 사용법을 익히는 것이 주 업무다.

## ✓ 레지스터 (Register) - ⭐ 가장 중요

임베디드 프로그래밍의 본질은 **"특정 메모리 주소에 값을 써서 하드웨어를 제어하는 것"**이다. 이 특별한 메모리 주소를 **레지스터**라고 부른다.

### 1. Memory Mapped I/O (MMIO)
CPU 입장에서는 그냥 메모리에 값을 쓰는 것(`*addr = 1`)과 똑같다. 하지만 그 주소가 실제 메모리(RAM)가 아니라, **하드웨어 회로와 직결된 주소**라는 점이 다르다.

*   예: `0x400FF000` 번지는 메모리가 아니라 **"LED 스위치"**와 연결되어 있다. 여기에 `1`을 쓰면 전구가 켜진다.

### 2. 레지스터의 3가지 역할
하드웨어 매뉴얼(Reference Manual)을 보면 레지스터는 크게 3가지로 분류된다.

1.  **Control Register (설정/제어):** "ADC야, 지금 변환 시작해!", "통신 속도는 9600으로 해." (CPU $\rightarrow$ HW)
2.  **Status Register (상태 확인):** "변환 다 됐니?", "데이터 도착했니?", "에러 났니?" (HW $\rightarrow$ CPU)
3.  **Data Register (값 전달):** "여기 변환된 온도 값이야.", "이 데이터를 전송해줘." (Data Exchange)

### 3. S32K144 레지스터 제어 예시
```c
// 1. [Control] 포트 D의 15번 핀을 '출력(Output)' 모드로 설정하라.
// PTD: 포트 D 레지스터 묶음의 시작 주소
// PDDR: Pin Data Direction Register (방향 설정 레지스터)
PTD->PDDR |= (1 << 15);

// 2. [Data] 포트 D의 15번 핀에 'High(1)' 신호를 내보내라 (LED ON).
// PDOR: Pin Data Output Register (출력 값 레지스터)
PTD->PDOR |= (1 << 15);

```

# 4 ARM Cortex-M 개념

S32K144는 **ARM Cortex-M4F** 코어를 사용한다. 이 코어의 내부 구조를 이해해야 디버깅할 때 레지스터 창이 무엇을 의미하는지 알 수 있다.

## ✓ 코어 레지스터 (Core Registers)
CPU 내부에는 연산을 위해 데이터를 임시 저장하는 아주 빠른 저장소들이 있다.

*   **R0 ~ R12 (범용 레지스터):** 연산 데이터나 주소를 저장한다. 함수 호출 시 인자 전달(R0~R3)에도 쓰인다.
*   **R13 (SP, Stack Pointer):** 현재 스택 메모리의 위치(주소)를 가리킨다. 함수가 호출될 때마다 값이 줄어들고, 리턴하면 늘어난다.
*   **R14 (LR, Link Register):** 함수를 호출했을 때, **"돌아갈 주소"**를 저장한다.
*   **R15 (PC, Program Counter):** **"다음에 실행할 명령어의 주소"**를 담고 있다. 디버깅할 때 이 값이 가리키는 곳이 현재 실행 위치다.

## ✓ NVIC (Nested Vectored Interrupt Controller)
ARM Cortex-M의 핵심인 **인터럽트 컨트롤러**다.

*   **우선순위 (Priority):** 여러 인터럽트가 동시에 터지면 누가 먼저 실행될까? NVIC가 결정한다.
    *   **숫자가 작을수록 우선순위가 높다.** (0이 가장 높음)
*   **벡터 테이블 (Vector Table):** 인터럽트가 발생했을 때 실행할 함수(ISR)들의 주소를 모아놓은 표다. 코드의 가장 앞부분(0x00000000)에 위치한다.

## ✓ Exception vs Interrupt
*   **Exception (예외):** CPU 내부에서 발생하는 이벤트. (예: 0으로 나누기, 잘못된 메모리 접근(HardFault), 시스템 콜)
*   **Interrupt (인터럽트):** CPU 외부(주변장치)에서 발생하는 이벤트. (예: 버튼 눌림, 타이머 종료, 데이터 수신)

# 5 S32K144EVB를 다루기 위한 기초

NXP 환경을 배우기 전에 알아야 하는 도구와 문서 보는 법이다.

## ✓ S32DS (S32 Design Studio)
NXP에서 제공하는 **Eclipse 기반**의 통합 개발 환경(IDE)이다.

*   **SDK (Software Development Kit):** 레지스터를 직접 건드리지 않고도 하드웨어를 제어할 수 있게 미리 만들어둔 C 함수들의 모음이다. (예: `PINS_DRV_WritePin`)
*   **Processor Expert (PE):** 코드를 타이핑하는 대신, **GUI 화면에서 클릭**으로 핀 설정이나 클럭 설정을 하면 자동으로 `pin_mux.c`, `clock_man.c` 같은 초기화 코드를 만들어주는 도구다.

## ✓ 회로도(Schematic) 보는 법
코드를 짜려면 "빨간 LED가 몇 번 핀에 연결되어 있는지" 알아야 한다. 이때 회로도를 본다.

1.  회로도 PDF에서 "LED"를 검색한다.
2.  LED 기호 옆에 적힌 핀 이름(예: `PTD15`)을 찾는다.
3.  이 이름을 코드(`PTD15`)에 사용한다.

## ✓ Datasheet vs Reference Manual
가장 많이 헷갈리는 두 문서의 차이점이다.

| 문서 종류 | 내용 | 언제 보는가? |
| :--- | :--- | :--- |
| **Datasheet** | 칩의 물리적 스펙 (전압, 전류, 온도, 핀 배치도) | "이 핀에 5V를 넣어도 타지 않을까?" 궁금할 때. |
| **Reference Manual (RM)** | **레지스터 맵**, 기능 동작 원리, 프로그래밍 가이드 | **"ADC를 켜려면 어떤 레지스터를 건드려야 하지?"** 코딩할 때 필수. |

# 6 빌드/플래시/디버깅 기초

코드를 짰으면 보드에 넣고 실행해야 한다.

## ✓ 빌드 과정 (Build Process)
우리가 짠 C 코드는 기계가 이해할 수 없다. 변환 과정이 필요하다.

1.  **Compile:** `.c` 파일을 기계어 조각인 `.o` (Object) 파일로 변환.
2.  **Link:** 여러 `.o` 파일들과 라이브러리를 합쳐서 하나의 실행 파일(`.elf`)로 만듦. 이때 **Linker Script (`.ld`)**가 메모리(Flash/RAM) 배치를 결정한다.
3.  **Binary Generation:** `.elf`에서 디버깅 정보를 빼고 순수 기계어만 추출하여 `.hex`나 `.bin` 파일을 만든다 (실제 롬에 구워지는 파일).

## ✓ 디버깅 (Debugging)
`printf`만으로는 임베디드 버그를 잡을 수 없다. **하드웨어 디버거(OpenSDA)**를 사용해야 한다.

*   **Breakpoint (중단점):** 코드의 특정 줄에서 실행을 멈춘다.
*   **Step Over (F6):** 함수 안으로 들어가지 않고 한 줄 실행.
*   **Step Into (F5):** 함수 내부로 들어가서 한 줄 실행.
*   **Resume (F8):** 다음 중단점까지 쭉 실행.
*   **Variables / Registers View:** 멈춘 상태에서 변수 값이나 하드웨어 레지스터 값을 실시간으로 확인하고 변경할 수 있다. **이게 디버깅의 핵심이다.**

- Datasheet에서 핀 이름을 찾을 수 있다
- Reference Manual의 레지스터 구조를 읽을 수 있다

- SDK가 레지스터를 추상화한다는 것을 이해한다
- S32DS에서 프로젝트 생성 → 빌드 → 디버깅 가능
